# 研究记录与证据规范

## 1. 文档目的

本文件用于规范项目中的研究记录、运行档案和证据链要求。

本项目不仅要做出系统，还要研究“AI 辅助电力科研”本身，因此记录不是附属品，而是核心产出的一部分。

## 2. 基本原则

- 记录必须服务复盘，而不是服务表面展示。
- 证据必须能回链，而不是只有结论没有来路。
- 失败记录和成功记录同等重要。
- 研究记录必须同时支持工程调试和方法论研究。

## 3. 记录对象

每一轮研究运行都应至少留下以下对象：

1. 任务记录
2. evaluator 记录
3. 技能记录
4. 实验结果记录
5. 认知记录
6. 成果分级记录
7. 报告记录
8. 证据包

## 4. 任务记录要求

任务记录应说明：

- 研究对象
- 任务目标
- 场景边界
- 约束条件
- 基线
- 初始风险判断

任务记录的价值在于保证“后来人能看懂这个任务为什么值得做”。

## 5. evaluator 记录要求

evaluator 记录应说明：

- evaluator 的目的
- 使用了哪些指标
- 成功判据是什么
- 基线如何确定
- evaluator 可能有哪些盲区

若 evaluator 本身存在明显缺陷，应作为重要研究记录单独标注。

## 6. 技能记录要求

技能记录应说明：

- 使用了哪些已有技能
- 新建或修改了哪些技能
- 这些技能为何被选择
- 技能适用条件是什么
- 技能失败的条件是什么

若一次成功无法沉淀为技能，应说明为什么无法沉淀。

## 7. 实验结果记录要求

实验结果记录应说明：

- 本轮跑了什么
- 与基线差异是什么
- 指标变化如何
- 是否稳定复现
- 是否存在异常情况

不允许只记录“效果更好”而没有具体对比。

## 8. 认知记录要求

认知记录应区分：

- 候选认知
- 稳定认知
- 失败认知
- 冲突认知

每条认知至少应包含：

- 内容
- 证据来源
- 适用边界
- 不确定性说明
- 与旧认知的关系

## 9. 成果分级记录要求

每轮任务都必须留下成果分级记录，说明：

- 本轮属于拓玉、琢石、雕木还是绘墨
- 分级依据是什么
- 可以说到什么程度
- 不能说什么

若不做分级，后续报告一律不应进入正式沉淀。

## 10. 报告记录要求

报告记录必须满足：

- 有证据回链
- 有边界说明
- 有失败摘要
- 有下一步建议
- 与成果等级一致

报告不是营销材料，不得掩盖证据不足和失败路径。

## 11. 证据包要求

证据包应能把以下对象关联起来：

1. 任务定义
2. evaluator 配置
3. 技能版本
4. 实验结果
5. 基线对比
6. 认知卡片
7. 成果等级
8. 报告结论

证据包的作用是让后继者可以追问：

- 这个结论从哪里来
- 用了什么技能
- 相比谁更好
- 为什么相信它
- 它的边界是什么

## 12. 失败的记录义务

以下失败必须被记录，而不是被清理掉：

1. evaluator 设计失败
2. 技能探索死路
3. 基线比较不成立
4. 认知解释悬空
5. 成果分级被强制降级

本项目中的失败记录是认知网络的重要来源。

## 13. 面向“AI 辅助科研研究”的附加记录

由于本项目本身还要研究 AI 辅助科研，因此每轮运行还应尽量补充：

- Agent 在哪里表现出良好科研习惯
- Agent 在哪里表现出幻觉或过度包装倾向
- 哪个 harness 约束起作用了
- 哪个 prompt 或流程约束没有起作用

这些观察是未来总结规律的重要材料。

## 14. 文档层级建议

建议将记录分成三层：

### 14.1 运行层

用于机器执行和排错。

### 14.2 研究层

用于总结一次任务的发现、失败和认知变化。

### 14.3 方法论层

用于总结 Agent 行为模式和框架设计经验。

这样可以避免把“运行日志”误当成“研究结论”，也避免把“研究结论”误当成“框架规律”。

## 15. 不允许的记录退化

以下情况说明记录制度已失效：

1. 只有最终报告，没有过程材料。
2. 只有成功样本，没有失败样本。
3. 只有结论，没有证据回链。
4. 只有代码结果，没有认知变化。
5. 只有任务完成，没有对 AI 行为的观察。

若出现这些情况，应先修复记录体系，再扩张任务规模。
