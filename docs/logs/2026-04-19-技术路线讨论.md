## 讨论入口问题

本轮讨论聚焦三条候选技术路线：

1. 直接 Python 脚本调用 LLM
2. 基于 LangChain 或类似框架构建 Agent 环境
3. 基于成熟 Agentic Coding 环境，并通过 harness 改造为科研专用 Agent

## 本轮讨论要解决的事

1. 路线选择不是纯工程便利性问题，而是研究范式问题
2. 需要判断哪条路线最适合承载：
   - 技能开发
   - 认知沉淀
   - 成效验证
   - 品味约束
3. 需要明确是否应采用混合路线

## 当前阶段判断

到当前阶段，已经形成较明确结论：

### 结论 1

纯 Python 脚本路线适合作为科研控制平面，但不适合作为唯一执行底座。

### 结论 2

通用 Agent 工作流框架可借鉴其编排思想，但不适合作为当前项目的核心承载体，否则容易重新回到“流程陷阱”。

### 结论 3

成熟 Agentic Coding 环境非常适合作为技能开发和任务执行的底座，但不能天然承担认知比较、文献对齐和品味控制。

### 结论 4

当前最合理的技术路线是：

- Agentic Coding 环境承担执行层
- 显式 Python 框架承担科研控制平面
- 文献对齐与比较认知升级作为独立能力层继续发展
