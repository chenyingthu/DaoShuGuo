# 运行时执行与状态机规范

## 1. 文档目的

本文件定义一次自主科研任务在运行时的标准状态流转、阶段输入输出、停止条件和异常分支。

其目的不是制造僵硬流程，而是保证每一次探索都留下结构化轨迹，并避免把“过程很忙”误判为“研究有进展”。

## 2. 总体原则

- 状态机服务研究闭环，不服务流程表演。
- 阶段之间必须有清晰交接物。
- 每个阶段都必须有停止条件。
- 没有通过当前阶段的最小要求，不得进入下游阶段。

## 3. 标准状态

一次任务运行采用以下标准状态：

1. `problem_framing`
2. `effectiveness_compilation`
3. `skill_retrieval`
4. `skill_evolution`
5. `evaluation_review`
6. `cognition_extraction`
7. `taste_grading`
8. `reporting`
9. `writeback`
10. `completed`

失败或中止状态：

- `blocked`
- `invalid_task`
- `failed_experiment`
- `insufficient_evidence`

## 4. 各阶段说明

### 4.1 problem_framing

目标：

- 澄清问题定义、任务价值、场景边界、成效指标需求和风险。

输入：

- 用户意图
- 领域背景
- 历史记录

输出：

- 任务说明
- 约束集
- 风险提示
- 待编译目标

停止条件：

- 问题对象明确
- 场景边界明确
- 目标方向明确

禁止跳过：

- 若问题对象和边界都不清，后续一律不进入技能阶段

### 4.2 effectiveness_compilation

目标：

- 将目标转化为 evaluator、基线和成功判据。

输入：

- 任务说明
- 约束集

输出：

- evaluator 定义
- 指标集合
- 基线定义
- 成功阈值

停止条件：

- evaluator 可独立执行
- 指标可比较
- 基线合理

异常：

- evaluator 不成立 -> 返回 `problem_framing`

### 4.3 skill_retrieval

目标：

- 在已有技能中找到最可能有效的技能或技能链。

输入：

- 任务说明
- 认知子集
- 技能注册表

输出：

- 技能检索结果
- 候选组合方案
- 缺失能力清单

停止条件：

- 已有技能足够直接尝试
- 或明确需要进入新技能构建

### 4.4 skill_evolution

目标：

- 在 evaluator 驱动下修改、组合或新建技能。

输入：

- 候选技能方案
- evaluator
- 历史失败记录

输出：

- 技能运行结果
- 技能变更记录
- 失败摘要

停止条件：

- 达到 evaluator 最低成功要求
- 或连续失败达到预设阈值

异常：

- 长时间无有效变化 -> 转入 `failed_experiment`

### 4.5 evaluation_review

目标：

- 审查技能运行结果是否真实构成进步。

输入：

- evaluator 输出
- 基线结果
- 复现实验

输出：

- 结果审查结论
- 是否达到有效成效
- 是否需要补跑或回退

停止条件：

- 能明确判断有效、无效或证据不足

异常：

- 证据不足 -> `insufficient_evidence`

### 4.6 cognition_extraction

目标：

- 从成功或失败结果中提炼认知候选。

输入：

- evaluator 结果
- 技能实现信息
- 历史认知

输出：

- 候选认知
- 失败认知
- 适用边界
- 冲突记录

停止条件：

- 至少形成一条结构化认知候选或明确“不足以形成认知”

### 4.7 taste_grading

目标：

- 对本轮成果进行“玉石木墨”分级，并给出 claim 上限。

输入：

- 结果审查结论
- 认知解释
- 复现情况

输出：

- 成果等级
- 等级理由
- 风险与表达限制

停止条件：

- 得到明确等级或明确判定为证据不足

### 4.8 reporting

目标：

- 在成果等级与 claim 约束下生成诚实报告。

输入：

- 任务信息
- 结果
- 认知候选
- 成果等级

输出：

- 任务报告
- 失败摘要
- 后续建议

停止条件：

- 报告与成果等级一致
- 报告可回链证据

### 4.9 writeback

目标：

- 将稳定技能和稳定认知写回系统资产层。

输入：

- 技能结果
- 认知结果
- 成果等级
- 证据包

输出：

- 技能写回
- 认知写回
- 运行档案

停止条件：

- 写回成功
- 证据链完整

## 5. 关键回退规则

以下情况必须回退，而不是强行推进：

1. 目标不清 -> 回退到 `problem_framing`
2. evaluator 失效 -> 回退到 `effectiveness_compilation`
3. 技能无效且无清晰失败认知 -> 回退到 `skill_retrieval`
4. 结果证据不足 -> 回退到 `evaluation_review` 或补实验
5. 认知解释明显悬空 -> 不得进入高等级报告

## 6. 失败状态的研究价值

失败状态不是纯粹终止信号，而是研究材料。

### 6.1 blocked

表示外部条件不足或基础设施未就绪。

应输出：

- 阻塞点
- 解除条件
- 当前不可继续的原因

### 6.2 invalid_task

表示问题定义本身不成立或当前条件下不可操作。

应输出：

- 为什么任务无效
- 需要怎样重写问题

### 6.3 failed_experiment

表示技能探索未得到有效结果。

应输出：

- 失败路径摘要
- 重复失败模式
- 候选负向认知

### 6.4 insufficient_evidence

表示结果可能有价值，但证据不足以支持主张。

应输出：

- 还缺什么证据
- 当前最多能说到什么程度

## 7. 最小运行日志要求

每个阶段至少要记录：

1. 输入摘要
2. 核心动作
3. 输出摘要
4. 停止原因
5. 风险或异常

## 8. 不允许的运行时退化

以下情况说明状态机正在退化为表演性流程：

1. 阶段名称很多，但没有明确输入输出。
2. evaluator 失败后仍强行推进到报告。
3. cognition_extraction 变成“随便总结两句”。
4. taste_grading 被跳过。
5. writeback 没有证据绑定。

若发生上述情况，应优先修复运行协议，而不是增加更多阶段。
