# 资产与证据对象契约草案

## 1. 文档目的

本文件给出第二批对象的具体契约草案。

这些对象位于资产层、派生判断层和表达层：

1. `Skill`
2. `Cognition`
3. `Taste Assessment`
4. `Evidence Bundle`
5. `Report`

## 2. 设计定位

这些对象不是同一层次：

- `Skill` 和 `Cognition` 是长期资产对象。
- `Taste Assessment` 是派生判断对象。
- `Evidence Bundle` 是回链组织对象。
- `Report` 是表达汇总对象。

必须避免把它们混成一个“大总结”。

## 3. 通用封套

建议与核心对象共用同一公共封套：

- `schema_version`
- `object_type`
- `object_id`
- `object_version`
- `created_at`
- `updated_at`
- `status`
- `metadata`

推荐附加：

- `tags`
- `extensions`
- `experimental`

## 4. Skill 契约草案

### 4.1 对象意义

`Skill` 表示一个可复用的执行能力资产。

它可以是基础能力，也可以是复合技能链。

### 4.2 Skill 必填核心

- `object_id`
- `object_version`
- `name`
- `capability_statement`
- `input_contract`
- `output_contract`
- `applicability`
- `implementation_ref`

### 4.3 Skill 建议字段

- `dependency_refs`
- `replacement_refs`
- `origin_run_refs`
- `validation_refs`
- `failure_conditions`
- `maturity_level`
- `usage_notes`

### 4.4 字段语义建议

- `capability_statement`
  用一句话说明该技能究竟做什么。

- `input_contract`
  说明期望输入是什么。

- `output_contract`
  说明稳定输出是什么。

- `applicability`
  说明适用场景和边界。

- `implementation_ref`
  指向代码、脚本或组合实现。

### 4.5 Skill 校验规则

- 没有输入输出契约的技能不能注册为稳定技能。
- 没有 `validation_refs` 的技能不能视为已验证技能。
- 没有 `applicability` 的技能不得被广泛复用。

## 5. Cognition 契约草案

### 5.1 对象意义

`Cognition` 表示一条对研究对象的结构化理解。

它可以是：

- 候选认知
- 稳定认知
- 失败认知
- 冲突认知

### 5.2 Cognition 必填核心

- `object_id`
- `object_version`
- `cognition_type`
- `statement`
- `evidence_refs`
- `scope_boundary`
- `confidence_level`

### 5.3 Cognition 建议字段

- `related_concept_refs`
- `supporting_refs`
- `conflict_refs`
- `derived_from_run_refs`
- `uncertainty_notes`
- `promotion_status`
- `human_review_notes`

### 5.4 字段语义建议

- `cognition_type`
  建议枚举至少支持：
  `candidate`、`stable`、`failure`、`conflict`

- `statement`
  认知表达本体，应该简洁、可检验、可讨论。

- `evidence_refs`
  指向支持该认知的 run、result 或 evidence bundle。

- `scope_boundary`
  指出认知适用在何种问题、工况或条件下。

- `confidence_level`
  表达当前可信度，而不是成果等级。

### 5.5 Cognition 校验规则

- 没有 `evidence_refs` 的认知不得进入稳定态。
- 没有 `scope_boundary` 的认知不得写成普遍规律。
- 冲突认知必须显式保留冲突关系，不能静默覆盖旧认知。

## 6. Taste Assessment 契约草案

### 6.1 对象意义

`Taste Assessment` 用于表达一次成果分级判断。

它属于派生判断对象，不是原始事实。

### 6.2 Taste Assessment 必填核心

- `object_id`
- `object_version`
- `task_ref`
- `run_refs`
- `grade`
- `grade_reasoning`
- `claim_ceiling`

### 6.3 Taste Assessment 建议字段

- `risk_notes`
- `forbidden_claims`
- `recommended_report_type`
- `evidence_refs`
- `review_status`

### 6.4 字段语义建议

- `grade`
  受控枚举：
  `tuoyu`、`zhuoshi`、`diaomu`、`huimo`

- `grade_reasoning`
  说明为什么这么分级，必须基于证据和边界。

- `claim_ceiling`
  说明最多可以说到什么程度。

### 6.5 Taste Assessment 校验规则

- `grade` 必须来自受控枚举。
- `grade_reasoning` 不得只写空泛褒贬词。
- 没有 `run_refs` 的分级不成立。

## 7. Evidence Bundle 契约草案

### 7.1 对象意义

`Evidence Bundle` 用于绑定高层结论和底层事实之间的链路。

它不是简单文件列表，而是“这个结论依赖什么”的结构化说明。

### 7.2 Evidence Bundle 必填核心

- `object_id`
- `object_version`
- `task_ref`
- `evaluator_ref`
- `run_refs`
- `artifact_refs`
- `claim_scope`

### 7.3 Evidence Bundle 建议字段

- `skill_refs`
- `cognition_refs`
- `taste_assessment_ref`
- `report_refs`
- `evidence_notes`
- `gaps`

### 7.4 字段语义建议

- `artifact_refs`
  指向任务文件、代码、日志、结果文件等实际材料。

- `claim_scope`
  指出这个证据包打算支持哪类结论，而不是“支持一切”。

- `gaps`
  明确还缺哪些证据。

### 7.5 Evidence Bundle 校验规则

- 没有 `run_refs` 的证据包不能支撑运行级结论。
- 没有 `artifact_refs` 的证据包不可审计。
- 没有 `claim_scope` 的证据包容易被滥用，应视为不完整。

## 8. Report 契约草案

### 8.1 对象意义

`Report` 是面向人类阅读的表达对象。

它用于诚实讲述一次任务，而不是重新定义事实。

### 8.2 Report 必填核心

- `object_id`
- `object_version`
- `task_ref`
- `report_type`
- `title`
- `summary`
- `evidence_bundle_refs`
- `taste_assessment_ref`

### 8.3 Report 建议字段

- `audience`
- `boundary_statement`
- `failure_summary`
- `next_steps`
- `claim_summary`
- `appendix_refs`

### 8.4 字段语义建议

- `report_type`
  建议枚举支持：
  `paper_draft`、`technical_note`、`experiment_record`、`discussion_memo`

- `summary`
  提供面向人的概述，但不得替代底层结构化对象。

- `boundary_statement`
  显式说明结论边界和不确定性。

### 8.5 Report 校验规则

- 没有 `evidence_bundle_refs` 的报告不应进入正式沉淀。
- 没有 `taste_assessment_ref` 的报告不得发表强结论。
- `report_type` 必须与成果等级相容。

## 9. 对象间引用关系建议

建议至少形成以下引用链：

- `Skill.origin_run_refs -> Run.object_id`
- `Cognition.derived_from_run_refs -> Run.object_id`
- `Taste Assessment.run_refs -> Run.object_id`
- `Evidence Bundle.run_refs -> Run.object_id`
- `Evidence Bundle.skill_refs -> Skill.object_id`
- `Evidence Bundle.cognition_refs -> Cognition.object_id`
- `Report.evidence_bundle_refs -> Evidence Bundle.object_id`
- `Report.taste_assessment_ref -> Taste Assessment.object_id`

## 10. 资产层和表达层的边界警戒线

以下情况说明边界开始混乱：

1. Skill 开始写成长篇研究结论。
2. Cognition 失去证据引用，变成纯随笔。
3. Taste Assessment 被写进 Report 正文但没有独立对象。
4. Evidence Bundle 退化成“附件目录”。
5. Report 被当成稳定事实源。

这些情况一旦出现，后续扩展和比较会非常困难。
