# 项目总设计方案

## 1. 项目定位

本项目的目标不是开发一个通用“科研自动化助手”，而是构建一个面向电力系统研究的自主科研 Agent 框架，并将该框架本身作为研究对象。

项目具有三重身份：

1. 软件系统：实现一个可运行、可扩展、可验证的 Agentic Research 框架。
2. 实验平台：用于研究 AI 如何辅助电力科研、在哪些环节有效、哪些环节容易失真。
3. 方法论装置：沉淀优秀研究生开展科研的视角、逻辑、习惯与品味，为后续研究者提供路径。

## 2. 核心问题

项目围绕以下问题展开：

1. 怎样将一个 Agent harness 成“合格科研研究生”。
2. Agent 的科研能力主要来自模型能力、工具能力、评价函数、记忆结构，还是它们之间的耦合。
3. AI 在电力科研中的最佳位置是替代、增强还是重构。
4. 哪些任务适合 Agent 主导，哪些任务必须人机协同。
5. 如何避免 Agent 因强表达能力而制造“成果幻觉”。

## 3. 理论核心

本项目采用“技能 - 认知 - 成效”三要素作为系统核心资产，而不是以流程为中心。

### 3.1 技能

技能是可复用的研究能力沉淀，表现为算法、脚本、模块、实验协议、数据处理链和标准化工具接口。

系统要求：

- 技能必须可调用。
- 技能必须有输入输出契约。
- 技能必须可验证。
- 技能必须可以组合、替代和版本化。

### 3.2 认知

认知是对研究对象及其规律的抽象理解，表现为概念、约束、定义、模型、假设、定理、经验边界和负向结论。

系统要求：

- 认知必须绑定证据来源。
- 认知必须说明适用边界。
- 认知必须能与已有认知形成关系。
- 认知冲突必须被显式记录和追踪。

### 3.3 成效

成效是外部可比较、可重复验证的结果改进。

系统要求：

- 成效优先于叙述。
- 成效评估必须独立于技能实现。
- 成效必须可以与基线比较。
- 没有成效证据，不得声称创新成立。

## 4. 系统总体结构

系统采用五层结构。

### 4.1 任务层

负责任务定义、问题边界、约束条件和目标拆解。

核心对象：

- 研究任务说明
- 场景约束
- 数据入口
- 基线定义
- 成效指标

### 4.2 成效层

作为系统的硬评价层和奖励函数层。

核心职责：

- 定义 evaluator
- 定义指标与阈值
- 运行比较实验
- 输出结构化结果
- 阻止“无证据的自我感觉良好”

### 4.3 技能层

作为系统的执行资产层。

核心职责：

- 检索已有技能
- 组装技能链路
- 开发新技能
- 将成功技能固化为可复用节点
- 记录组合效果与替代关系

### 4.4 认知层

作为系统的语义与理论记忆层。

核心职责：

- 提供问题语境
- 防止概念重造
- 吸收成功与失败经验
- 形成机制解释与边界分析
- 管理认知冲突和升级

### 4.5 编排层

作为状态机和工作流控制层。

核心职责：

- 根据阶段调用不同 Agent 角色
- 控制读写权限和上下文粒度
- 记录运行轨迹
- 触发写回技能网和认知网
- 生成证据包和研究日志

## 5. 双网持久演进机制

### 5.1 技能网络

技能网络是可执行资产图。

节点类型：

- 基础工具
- 复合工具链
- 数据适配器
- 求解器
- 评估辅助器

边类型：

- 依赖
- 输入输出匹配
- 替代
- 组合成功
- 版本继承

技能网络的目标不是做知识展示，而是支持实际调用决策。

### 5.2 认知网络

认知网络是证据约束下的语义图。

节点类型：

- 概念
- 规律
- 约束
- 经验结论
- 失败结论
- 冲突点

边类型：

- 支持
- 冲突
- 推导
- 限制
- 适用
- 引用证据

认知网络的目标不是堆文献，而是为研究判断提供结构化先验。

### 5.3 双网耦合

双网通过成效层耦合：

1. 认知网络指导技能检索和技能设计。
2. 技能网络在 evaluator 中产生结果。
3. 成效结果决定技能是否固化。
4. 结果分析决定认知是否升级。
5. 新认知反过来改变下轮技能调用偏好。

## 6. 合格科研研究生 Agent 的目标画像

系统要模拟的不是“会执行命令的人”，而是“具备科研人格结构的研究者”。

目标画像包括四个维度：

1. 视角：先判断问题、价值、边界和已有认知，再行动。
2. 逻辑：遵循问题定义、假设、方法、验证、解释、边界的研究结构。
3. 习惯：记录、复盘、版本化、负结果管理、技能沉淀、认知更新。
4. 品味：识别成果等级，控制 claim 上限，拒绝“绘墨式”产出。

## 7. 品味作为系统内核

品味是项目最关键的能力，不应被视为软性修养，而要被实现为系统约束。

系统中的品味至少体现在以下四类判断：

1. 选题品味：问题是否重要，是否值得投入。
2. 成果品味：结果的质地是否足以支持更强结论。
3. 机理品味：成功结果是否值得上升为认知。
4. 表达品味：表达是否忠实于证据，不制造高估。

本项目采用“拓玉、琢石、雕木、绘墨”四级框架作为成果分级器。

## 8. 运行时状态机

最小闭环采用六阶段状态机：

1. Problem Framing
2. Effectiveness Compilation
3. Skill Retrieval and Assembly
4. Skill Evolution
5. Cognition Extraction
6. Reporting and Write-back

每个阶段都必须有输入契约、输出契约和停止条件。

## 9. 数据与证据原则

系统中的每个高层结论都要能追溯到以下对象：

- 任务定义
- 输入数据
- 技能版本
- evaluator 结果
- 对比基线
- 失败记录
- 认知卡片

没有证据链的“洞察”，只能算候选认知，不得进入稳定认知网络。

## 10. 最小可行产品范围

第一阶段只做最小闭环，不做大而全平台。

MVP 范围：

1. 单领域任务，限定为电力系统的一个小型问题。
2. 单 evaluator 框架。
3. 单技能注册表和轻量图结构。
4. 单认知注册表和认知卡片。
5. 单编排器。
6. 三类 Agent 角色。

不纳入第一阶段的内容：

- 大规模多智能体群体演化
- 重型图数据库依赖
- 自动论文写作系统
- 通用跨学科平台化

## 11. 第一阶段推荐切入点

建议选择一个很小但可验证的问题作为起点，例如：

- IEEE 33 节点配电网无功优化
- 小型微网调度
- 特定工况下的电压稳定控制

## 12. 技术路线选择结论

到当前阶段，项目已经明确不建议纯走以下任一路线：

1. 纯 Python 脚本直接调 LLM
2. 纯 LangChain/工作流框架
3. 纯 Agentic Coding 环境

### 12.1 路线 1 的定位

纯 Python 路线适合承担：

- evaluator
- schema
- registry
- evidence bundle
- 对照分析
- 文献对齐

但不适合作为唯一执行底座。

### 12.2 路线 2 的定位

通用 Agent 框架适合提供编排思想，但容易让项目重新退回“流程陷阱”，即：

- 拥有看似完整的工作流
- 却缺乏足够强的科研控制力

### 12.3 路线 3 的定位

成熟 Agentic Coding 环境非常适合作为：

- 技能开发底座
- 代码调试底座
- 任务执行底座

但它不会天然提供：

- 认知比较
- 文献对齐
- 品味约束
- 证据结构

### 12.4 当前推荐路线

当前推荐路线为：

> 以成熟 Agentic Coding 环境作为执行底座，以显式 Python 框架作为科研控制平面，并在其上独立发展认知层能力。

## 13. 解耦与自律协同原则

本项目当前进一步明确：

> 系统不应被设计为“大一统单体 Agent”，而应被设计为由多个能力应用通过统一对象契约实现分散自律协同的科研系统。

### 13.1 为什么要强调解耦

高耦合开发在复杂科研系统中容易导致：

- 局部修改牵动全局
- 单点失败拖垮整体
- 开发节奏在复杂度上升后饱和
- 测试与部署变得困难

### 13.2 哪些耦合应尽量消除

- 运行时强耦合
- 开发强耦合
- 测试强耦合
- 共享可变状态耦合

### 13.3 哪些耦合必须保留

- 契约耦合
- 评价耦合
- 证据耦合

也就是说：

- 所有应用必须说同一种对象语言
- 所有高层主张都必须服从 evaluator 与 taste gate
- 所有高层认知都必须回链底层证据

### 13.4 自律协同的含义

自律协同在本项目中的含义是：

- 每个能力应用只对自己的输入输出和行为边界负责
- 协同依赖对象契约，而不是共享内部实现
- 某个应用未完成或失效，不应阻塞其余应用运行
- 所有应用都存在时，应形成分散但有序的科研生态

## 14. 文献对齐与比较认知升级层

当前系统已经具备：

- 真实执行
- 技能生成
- 结果比较
- 结构化对照分析

下一阶段进一步增加的，不应只是“更多运行”，而应是：

- 文献对齐
- 比较认知升级

### 14.1 为什么要新增这一层

因为结果比较只能告诉我们：

- 哪个策略在当前任务上更强

却不能告诉我们：

- 哪条认知更深
- 哪条解释更可信
- 当前技能与已有文献是什么关系
- 当前主张应晋升还是降级

### 14.2 建议新增能力

建议新增以下能力层：

1. Literature Alignment
2. Strategy Semantic Comparison
3. Novelty Assessment
4. Comparative Cognition Upgrade

### 14.3 目标

这层的目标不是增加一个“更会写总结”的模块，而是：

- 把认知比较对象化
- 把文献关系对象化
- 把认知晋升/降级规则对象化
- 将本地结果与外部知识共同纳入认知控制面

选择标准：

- 有清晰 evaluator
- 有公开基线
- 有可编程仿真环境
- 有明显失败和成功差异
- 足够小，能跑完整闭环

## 12. 交付物规划

第一阶段应形成以下交付物：

1. 项目总设计文档
2. Agent 规范文档
3. 品味评估框架
4. 仓库级 AGENTS.md
5. MVP 目录结构
6. 第一版 orchestrator
7. 第一版 evaluator 接口
8. 第一版技能注册表和认知卡片结构

## 13. 成功标准

项目第一阶段的成功，不是“系统很复杂”，而是以下三点同时成立：

1. 能跑通一个真实小课题的完整闭环。
2. 能沉淀至少一个复用技能和一个有效认知。
3. 能输出一份诚实、分级清晰、不过度包装的研究报告。

## 16. 基本步骤与扩展步骤划分

为保证后续工作的延续性与推进节奏，项目当前明确区分：

- 基本步骤
- 扩展步骤

这里的“基本步骤”指系统第一次成立所必须跑通的最小闭环；
“扩展步骤”指显著增强系统质量与研究能力，但不应反向阻塞主线的能力。

### 16.1 基本步骤

当前阶段必须优先保证以下步骤持续成立：

1. `任务定义`
2. `技能执行`
3. `独立评估`
4. `结构化运行记录`
5. `最小认知提炼`
6. `品味约束`
7. `写回积累`

#### 任务定义

必须有清晰任务对象、边界、约束、基线和目标。

#### 技能执行

必须至少存在：

- 一个 baseline skill
- 一个 candidate skill

并且二者都能真实运行。

#### 独立评估

必须存在独立 evaluator。

#### 结构化运行记录

必须留下：

- run
- metrics
- evidence bundle
- report
- writeback

#### 最小认知提炼

必须至少做到：

- 成功时形成候选认知
- 失败时形成负向认知
- 认知带证据与边界

#### 品味约束

必须有：

- taste assessment
- claim ceiling
- report 受约束

#### 写回积累

技能和认知必须被写回 registry 或对象层。

### 16.2 第二优先级必要项

以下能力虽然不属于“闭环最小定义”，但已逐渐接近必要项：

1. `最小对照分析`
2. `最小解耦`

#### 最小对照分析

系统不应只有单点 baseline vs candidate 比较，而应具备最小的 candidate vs candidate 对照能力。

#### 最小解耦

当前阶段至少应守住以下边界：

- evaluator 独立
- run 独立
- report 不反向污染事实
- writeback 独立

### 16.3 扩展步骤

以下能力当前属于扩展项：

1. 文献对齐
2. 解释对齐
3. 新颖性评估
4. 精细化认知升级规则
5. 多任务迁移
6. 双网图化
7. 全文级文献抽取与综述

这些能力都很重要，但当前不应反向阻塞主线。

### 16.4 当前阶段执行原则

当前阶段的执行原则是：

> 扩展能力可以继续发展，但不能破坏和阻塞基本步骤闭环。

换句话说：

- 基本步骤决定系统是否成立
- 扩展步骤决定系统未来能走多远
