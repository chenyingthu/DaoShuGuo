# 工作原则与研发方法

## 1. 文档目的

本文件用于明确本项目的工作原则、实施方法和研发节奏，避免项目在执行中退化为“空泛讨论”或“局部忙碌”。

## 2. 总原则

### 2.1 先评价，后优化

任何技能演化或认知提炼，必须先有 evaluator、基线和成功判据。

### 2.2 先最小闭环，后系统扩张

先跑通一个真实小问题的完整链路，再扩展多智能体、图数据库和复杂记忆系统。

### 2.3 先证据，后叙述

所有高层结论都必须来源于可回溯证据，而不是叙述惯性。

### 2.4 先资产沉淀，后任务数量

项目价值不取决于跑了多少任务，而取决于沉淀了多少可靠技能和有效认知。

### 2.5 先诚实，后好看

系统必须优先暴露失败、边界和不确定性，不能以报告美观替代研究质量。

## 3. 研发方法

### 3.1 文档先行

先确定概念、边界、评价规则和目录结构，再推进原型实现。

### 3.2 闭环驱动

任何新增模块都必须回答：

1. 它属于哪个阶段。
2. 它服务哪类资产。
3. 它如何被验证。
4. 它失败时如何降级。

### 3.3 小步试验

所有重要机制都先用最小可行实现验证：

- 技能注册先用 JSON 和目录结构
- 认知卡片先用 Markdown 和元数据
- 图关系先用轻量索引，不急于引入重型组件

### 3.4 角色分离

至少区分以下工作角色：

- 任务建模
- 技能构建
- 成效评估
- 认知提炼
- 报告审核

即便这些角色由同一个底层模型执行，也要在系统层显式区分。

### 3.5 研究与工程并行

每个阶段既要产生工程产物，也要产生研究记录。

例如：

- 工程产物：orchestrator、evaluator、registry
- 研究记录：实验日志、失败总结、对 AI 行为模式的观察

## 4. 实施节奏

### Phase 0: 总纲固化

目标：

- 形成项目总设计
- 固化 Agent 规范
- 固化品味框架
- 固化仓库级 AGENTS.md

### Phase 1: MVP

目标：

- 选定一个小型电力任务
- 完成 evaluator
- 完成单任务闭环
- 完成技能与认知写回

### Phase 2: 质量门控

目标：

- 增加成果分级器
- 增加 claim 审核器
- 增加失败知识化机制

### Phase 3: 双网增强

目标：

- 引入轻量图结构
- 增加技能路径选择
- 增加认知子图检索

### Phase 4: 扩展实验

目标：

- 对多个电力问题复用同一框架
- 比较不同 harness 和 prompt 的影响
- 研究 AI 辅助科研的规律和边界

## 5. 研发中的禁忌

项目执行中不得出现以下倾向：

1. 没有 evaluator 就开始大规模调方法。
2. 没有基线比较就宣称有效。
3. 用多智能体复杂性掩盖评价体系不成熟。
4. 用知识库堆积替代认知结构建设。
5. 用写作和排版替代研究质量。
6. 把局部成功误判为系统成熟。

## 6. 记录制度

每一轮任务都要至少产出以下记录：

1. 任务定义
2. evaluator 配置
3. 采用技能
4. 新增技能
5. 关键失败
6. 新增认知
7. 成果等级
8. 下一轮建议

## 7. 面向后继者的要求

本项目必须服务“为后来人指路”的目标，因此所有关键设计都应尽量满足：

- 可解释
- 可复现
- 可迁移
- 可批判

如果某项设计只能“勉强跑通”，但无法被后继者理解和复用，则应谨慎引入。
